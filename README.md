# Brush presets: bounded writes and retained failed creation drafts

Follow-up in existing [PR #5352](https://github.com/storytold/photocraft/pull/5352). Before source: 9f0dcb5e09f44b17a4861e1f8cda05debeee8de3; after source: 359bab9366cbbbb3dba80fd7cff0f4bba84dd1ea.

Preset Save/Update omit the size/Scatter validator used by tools.setBrush and painting. For example, saving size 5001 succeeds, but selecting that preset fails at the existing 5000 maximum. Replacing/updating a good preset can persist settings rejected by the selector. Separately, the New Brush Preset dialog is removed before its action runs, so an invalid-name confirmation through automation discards the draft on error.

Use the existing validate_brush at both write boundaries, before library/revision/selection mutations. Keep the brush-preset draft until its save succeeds. Existing Guide Layout validation/dispatch precedence and other dialog paths are retained. No new numeric ranges, colour-capture semantics, command IDs or file formats are introduced.

The new engine regression fails at the before revision. It covers seven invalid patches across new save, replacement save, current update and named update (28 cases). Rejection preserves the entire preset library, working brush/selection/colours/revisions/gesture, journal, remembered brush and bytes in an attached MemBackend store. Valid inclusive size/Scatter maxima/minima and inactive settings remain accepted and replayable. The UI regression also fails before: duplicate confirmation closes its draft. It now covers fourteen themes, duplicate rejection, invalid size by pointer and Enter, retained fields/capture choices, unchanged working state, and one successful corrected retry. The original five new tests remain in this PR; two tests are added by this follow-up.

Full engine and UI + HEIF/examples/doctests: 4571 passed, zero failed, 31 ignored across 83 test/doc groups. Strict all-target Clippy (-D warnings), fmt, parity generation, ignored panic_hunt, layers and wasm passed.

Ten inspected native full-app egui/wgpu captures use the same original driver on both revisions. Open the real Brush Settings panel menu and its shared dialog, then supply fields through public ui.dialog.set. Size 5001, active Scatter 11, duplicate-name control confirmation, 2x and a valid control are covered. These are automation-supplied settings; ordinary sliders already constrain their values. Before, numeric-invalid saves append one preset and close the form; a subsequent tools.setBrush selection proves that stored preset unusable. Duplicate confirmation returns an error and closes the form without saving. After, invalid settings are rejected without writing and the original dialog/fields remain; correction and a single successful retry are verified. The valid control is pixel-identical. State JSON records command counts, preserved state and control replies. This is not a brush-rendering or new crash fix; closed #977 is only historical context for the reused numeric guard.
